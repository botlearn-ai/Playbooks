# 你需要的不是更多 Skill，而是 Skill Pack

> **关联章节**：第 2 天 — 第一个真实任务
> **阅读时间**：约 6 分钟
> **读完之后你会明白**：为什么安装更多 Skill 会让你的 Agent 变差——以及选择安装什么的正确心智模型

---

当人们第一次发现 ClawHub 时，本能反应是自然的：更多 Skill = 更聪明的 Agent。浏览注册表，把看起来有用的全装上，然后看着 Agent 升级。

这恰恰是错的。

原因如下——以及正确的做法。

---

## 太多 Skill 的 4 个隐性代价

### 1. 智能退化（混乱）

在 Agent 回答任何问题之前，它会读取每一个已安装 Skill 的描述，并将其加载到上下文窗口中。这是它知道有哪些工具可用的方式。

装了 700 个 Skill，Agent 80% 的工作记忆在还没有开始实际思考之前，就已经被消耗在读工具列表上了。留给推理的上下文越少，输出就越差。你的 Agent 不会因为选项更多而变聪明，只会变得更混乱。

### 2. 决策瘫痪（歧义）

很多 Skill 在功能上重叠。`write_file`、`edit_file`、`append_file`——都是写文件。`web_fetch`、`web_scrape`、`browser_use`——都是获取网页内容。

当你的 Agent 有 10 个工具都能"写文件"时，它会把推理周期浪费在选择上。在歧义情况下，它可能选错，或者卡住不动。更少、更清晰的工具，带来更快、更可靠的执行。

### 3. 安全风险

你安装的每一个第三方 Skill，都是在你的机器上运行的代码，可以访问你的 Agent 上下文、你的文件系统，以及可能的凭证。安装的 Skill 越多，攻击面越大。

2026 年 2 月，安全研究人员在 ClawHub 上识别出 341 个以上的恶意 Skill，这些 Skill 从受影响机器上窃取了 SSH Key 和 API Token。每一个看起来都是合法的。攻击向量很简单：安装、运行、窃取。

你安装的第三方 Skill 越少，你的暴露面越小。

### 4. 成本爆炸（Token 消耗）

每次对话都会把你的完整 Skill 列表发送给 LLM。更多 Skill = 每次请求更多 Token = 更高的 API 费用。一个庞大的 Skill 注册表，可能让你在每条消息上都为数百个工具描述付费——包括那些根本不需要用工具的简单消息。

---

## 正确原则：从最小化开始，有意识地添加

> 只安装你需要的。优先使用内置 Skill。只有当内置选项真的无法完成工作时，才安装第三方 Skill。

### 原则 1 — 优先使用内置 Skill

OpenClaw 自带一套内置 Skill，经过预验证、依赖最少，由 OpenClaw 团队维护。这些是你的默认选项。

在从 ClawHub 安装任何东西之前，先检查内置 Skill 是否已经能覆盖你的需求。大多数常见任务——网络搜索、文件管理、发送消息、读取文档——内置 Skill 已经开箱即用。

### 原则 2 — 新 Skill 的三重过滤测试

安装任何 Skill 之前，先做这个测试：

**高频使用** — 你会每天或每周用到这个 Skill 吗？如果是一次性任务，考虑手动完成，或用现有 Skill 组合实现。

**替代真实劳动** — 这个 Skill 是否能显著减少重复性手工工作？节省 5 秒的自动化不值得它带来的复杂度。

**受控权限** — 这个 Skill 要求的访问权限是否超出了任务实际需要？避免安装申请广泛文件系统访问权、连接未知端点的网络访问权，或出于不明原因要访问你的凭证的 Skill。

三条都通过了，再安装。

---

## 如何安装 Skill（4 种方式，按安全性排序）

### 方式 1 — 内置 Skill（推荐）

随 OpenClaw 预装，无需安装步骤，直接启用。只需关注本地依赖是否满足（如 `brew` 包）。

已验证、低风险，应该是你的第一选择。

### 方式 2 — 控制台 / 图形界面

通过 OpenClaw 内置的 Skill 库界面浏览和安装。方便，且相对安全——库是经过筛选的。但安装前仍需检查：作者身份、安装数量、Skill 来源。

### 方式 3 — CLI / 注册表（`clawhub install`）

通过 ClawHub 或其他外部注册表安装，可以访问完整的社区 Skill 生态。这是最灵活的选项——也是风险最高的。

只安装你认识或经过验证的作者的 Skill。运行之前先阅读 `SKILL.md` 源码。有疑问，不安装。

```bash
clawhub install author/skill-name
```

### 方式 4 — 本地手动安装

因为 Skill 只是一个目录加一个 `SKILL.md`，你可以完全把 Skill 作为本地资产管理：

- 从可信仓库克隆到你的本地 Skill 目录
- 用 Git 做版本控制
- 运行前审查每次变更

这给你完整的可审计性，是生产环境或任何安全敏感部署的正确选择。

## Skill 和 Skill Pack 有什么区别？

**Skill** 是单一能力：`web_fetch`、`send_telegram`、`summarize_pdf`。

**Skill Pack** 是为特定工作流协同设计的一组 Skill 的集合。你在第 2 天设置的早间简报不是单一 Skill——它是一条由采集、筛选、合成、推送 Skill 依次工作的 Pipeline。

这个区别之所以重要：

- 单独安装 Skill 然后期望它们自动组合好，会导致上述的碎片化问题
- 设计良好的 Skill Pack 替你处理了组合问题——这些 Skill 是配套选择的，作为一个整体测试的，为端到端工作流优化的

评估安装什么时，以工作流为单位思考，而不是以单个能力为单位。"我需要一个早间简报"才是正确的出发点——而不是"我需要一个 RSS 阅读器、一个摘要工具和一个 Telegram 发送器"。
