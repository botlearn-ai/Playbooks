# 理解你的 Agent 智能 — 4C 框架 🧠

> **关联章节**：第 1 天 — 激活
> **阅读时间**：约 5 分钟
> **读完之后你会明白**：你的第 1 天分数为什么长这样——以及最快的提升路径

---

你刚拿到了第一份能力评分。这是它背后的思维模型。

OpenClaw 不是聊天机器人，它是一个可编程 Agent——它的智能来自四个层次协同工作，很像一个人在学习一份新工作。

---

## 四层智能架构

### 1. Core — 大脑

底层 LLM（Claude、Gemini、GPT 等）。提供原始推理能力、逻辑能力和通用世界知识。这是你的 Agent 的天赋——目前固定不变，但是其他一切的基础。

### 2. Context — 记忆 ⭐ 最重要

你向 Agent 注入的特定信息：你的项目、你的团队、你的历史、你的目标。这是让 Agent 认识*你*的东西。

一个对你的工作一无所知的天才，远不如一个对你的业务了如指掌的普通助手有用。Context 是乘数。

这就是第 4 天存在的原因。配置 `SOUL.md`、`USER.md` 和 `AGENTS.md` 就是上下文注入——这是你能做的、对提升 Agent 表现杠杆最高的单一操作。

### 3. Constitution — 灵魂

在 `SOUL.md` 中定义的人格和运作规则。决定你的 Agent *如何*思考和行动：

- 它是否快速行动、偏向执行？
- 它是否在每一步之前都提问澄清？
- 它的语气是正式还是随意？
- 它是作为顾问还是执行者？

你来定义性格。没有 `SOUL.md`，你的 Agent 默认进入通用助手模式——有帮助、谨慎，但对完成真正的工作几乎没用。

### 4. Capabilities & Skills — 双手 🛠️

Agent 能够执行的具体技能。这是推理转化为行动的地方。

| Skill 类型 | 示例指令 |
|---|---|
| 网络搜索 | "查找 X 的最新新闻" |
| 文档分析 | "读这份 PDF，提取关键决策" |
| 数据处理 | "把这张表格转换成 JSON 文件" |
| 定时自动化 | "每天早上 7:30 运行这个任务" |
| 通信推送 | "把这份摘要发到我的 Telegram" |

Skill 通过 ClawHub 安装——把它们理解为手机上的 App。它们扩展了你的 Agent *能做什么*，而不改变它本质上*是什么*。

## 如何让你的 Agent 更聪明：3 个步骤

你的 Agent 起点潜力高但经验为零。4C 框架告诉你该把精力投在哪里。

### 第 1 步 — 喂给它上下文（上传）

不要只是提问，要提供背景材料。

```
Read this project brief and save the key points to memory.
```

Agent 拥有的相关上下文越多，它在所有后续任务上的判断就越好。

### 第 2 步 — 定义它的角色（简报）

不要满足于通用助手。为特定任务告诉它该扮演谁。

```
Act as a Senior Product Manager. Critique this PRD focusing on edge cases and missing constraints.
```

角色框架激活正确的推理模式，显著提升输出质量——即便在你还没有配置 `SOUL.md` 之前。

### 第 3 步 — 安装新 Skill（升级）

当你需要 Agent 做一件新的事情时，先检查 Skill 库。

```
I need to analyze an Excel file. Do you have a data analysis skill installed?
```

如果 Skill 可用，安装它。如果没有，通常可以用现有 Skill 组合完成任务，或者让 Agent 用通用工具尝试。

## 为什么你的第 1 天分数长那个样子

在相同 LLM 和相同已安装 Skill 的条件下，你的 Agent 的有效智能等于：

> **上下文密度 + 指令清晰度 + 工具就绪度**

**上下文密度** — Agent 对你、你的角色和你的目标拥有多少相关信息。第 1 天时，这接近于零。`USER.md`、`SOUL.md` 和 `AGENTS.md` 还没有写，这就是为什么"记忆与上下文"维度得分低。

**指令清晰度** — Agent 对自己的运作规则理解得多精准。没有 `SOUL.md` 和 `AGENTS.md`，它默认谨慎、通用的行为。这体现在"质量与准确性"和"创意生成"维度的较低得分上。

**工具就绪度** — 有多少相关 Skill 已安装并可正常使用。第 1 天只有默认配置。这反映在"工具使用"和"代码生成"维度的得分上。

7 天协议的每一天都在改善这三个变量中的一个或多个：

| 协议天数 | 改善的内容 |
|---|---|
| 第 1 天 | 基准测量——了解你的起点 |
| 第 2 天 | 工具就绪度（第一条 Skill 管道已安装） |
| 第 3 天 | 指令清晰度（安全基线 = 信任 + 边界） |
| 第 4 天 | 上下文密度 + 指令清晰度（SOUL、USER、AGENTS 已配置） |
| 第 5 天 | 工具就绪度 + 上下文密度（真实工作流已部署） |
| 第 6 天 | 三者全部（自我改进循环启动） |
| 第 7 天 | 完整增量测量——精确看清你走了多远 |

到第 7 天，你的分数将反映一个知道你是谁、知道你需要什么、知道如何把事情完成的 Agent。
